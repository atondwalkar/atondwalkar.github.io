The Heterogeneous system features a General Purpose Processor (GPP) with a small RISC instruction set along with special instructions to interact with the tensor subsystem. The GPP is a pipelined single core processor that performs normal operations while offloading neural network calulations or matrix operations in a systolic array.

A DMA transfers array data from the Data Memory (DM) to arrays of FIFOs that propagate this data into the systolic array. The GPP provides the DMA with information about the array which includes memory location, row and column dimensions, and which FIFO array to target. Targetting FIFO arrays A and B will prompt the DMA to transfer data to the FIFOs, while targetting FIFO X will pop the product data into the DM. When a transfer is initiated, the DMA will compute the final address location and then continuously fetch consecutive words from the DM or FIFO X. The DMA also stores the arrays dimension data with the associated FIFO. The cache of the GPP snoops write from FIFO X to DM.

To perform the matrix multiplication, the GPP is given a special instruction to allow the systolic array to begin multiplying the matrices. The number of clock cycles required by the systolic execution is determined by the arrays' dimensions. The resulting matrix can be sent through a ReLU acitivation function, which is specified by the "start multiplication" instruction given to the GPP. It is likely the systolic array is not big enough to accomodate matrix sizes for a neural networks layer. Blockedwise matrix multiplication has to be perfomed for large matrices, which involves adding resulting vectors. Thus, the systolic array has a feature to allow "compression" of the vectors or element-wise addition.

A custom assembler for the system features multi-module linking, high level programming language pragma translations, and interrupt setups. The pragma translations were used for performing DMA transfers and performing matrix multiplications. The DMA was in a shared memory space as the DM and I/O, so it would be bothersome as a programmer to have several "loads" to setup a single transaction. The pragma takes arguments of array location, dimensions, and fifo target. The matrix multiplication pragma takes these arguments for two matrices and the activation function.

Benchmarks

Benchmarks were run on the system with a MNIST model. A custom DNN hardware implementation and a single core GPP was benchmarked against the system. A version of the program is also benchmarked against the system by performing the vector element-wise addition in the GPP, labelled as "Array and GPP" in the table. The presentation below shows the results of the benchmark at the bottom. It can be observed that the custom DNN hardware performed the best, but it is a poor solution because it cannot adapt to any other neural network. The GPP expectedly performed the poorest because the of the limited register file the the amount of loads and stores required, as well as the multiplication being perform in serial rather than in parallel. Utilizaiton shows that the AI accelerator requires a great amount of hardware, a vast majority of which is block memory.

Conclusion

The design of the AI accelerator in this system uses an impractically slow memory architecture using FIFOs. This design requires the FIFOs to start being popped before new matrix data can begin populated them. In practical implementations of AI accelerators, unified buffers or large memory banks are used in tandem with their multiplication hardware, which will allow data to populate the buffers in parallel with the matrix multiplication regardless of execution status. It is likely with a different implementation of the Accelerator that the utilization of block memory may increase.
